# Phase 6 — UI Design Contract: Memory Surface

> Visual and interaction contract for the operator-facing Memory surface ("What I know about you"). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase ships into an **established design system** (Preact + Tailwind v4 CSS-first + CSS-variable tokens). The contract below pins the surface to that existing system; it does NOT introduce a new one. The closest precedents are `web/src/pages/Activity.tsx` and `web/src/pages/Audit.tsx` (operator-vs-technical split, 04 D-01 / 05 D-01).

## Spacing Scale

The project's de-facto scale (Tailwind utilities; all multiples of 4 except the documented pill exception below). Match the analog surfaces exactly.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, pill horizontal padding (`gap-1`, `px-1.5`→6, `py-1` for buttons) |
| sm | 8px | Compact element spacing, tab gaps (`gap-2`, `mb-2`) |
| md | 16px | Default card-to-card gap, content padding (`gap-4`, `py-4`) |
| lg | 24px | Page horizontal padding, category-group bottom margin (`px-6`, `mb-8`→32) |
| xl | 32px | Major group breaks between categories (`mb-8`) |
| 2xl | 48px | Reserved — not expected on this surface |
| 3xl | 64px | Reserved — not expected on this surface |

**Card anatomy (mandatory, mirrors `ActivityRowCard`):** fact row = `bg-[var(--color-elevated)] border border-[var(--color-border)] rounded-md p-3`, rows stacked with `gap-4`, category groups separated by `mb-8` with a `mb-2` section label.

**Exception (sole, justified):** the `Pill` component uses `py-0.5` = **2px** vertical padding. This is intentional for dense pill height (10px label inside a compact tag) and is the established, shipped `Pill` convention reused verbatim across Activity/Audit. It is the only sub-4 value permitted on this surface; everything else is a multiple of 4 (`p-3`=12, `py-3`=12, `px-6`=24, `gap-4`=16). Do not introduce any other sub-4 spacing.

## Typography

The base font-size is 13px (`html` in `main.css`); this surface is dense by design. Declared roles (4 sizes, 2 weights):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Page title | 14px | 600 (semibold) | 1.2 (default) |
| Fact text (body) | 12.5px | 400 (regular) | 1.4 (`leading-snug`) |
| Meta / provenance label | 11px | 400 (regular) | 1.5 |
| Section label (category headers) | 10px uppercase, `tracking-wider` | 500 (medium) | 1.5 |

**On the 12.5px body size (intentional, not a near-miss):** 12.5px = `text-[12.5px]`, the exact value `ActivityRowCard` uses for its plain-language phrase (the row this surface mirrors). It reads as "just under" the 13px base on purpose — fact text is the densest content on the surface and must pack into two-line rows, while the 14px title still reads a clear step above it. The 14 / 12.5 / 11 / 10 ladder is the shipped Activity/Audit scale; matching it verbatim keeps the two operator surfaces visually consistent. Do not substitute 12px or 13px for fact text.

**Weights:** exactly two — regular (400) for all content, semibold (600) for the page title and primary-button labels. The 500 (medium) on the 10px section label and on pills is the established `.section-label` / `Pill` convention and is treated as part of the label role, not a third content weight.

**Provenance is first-class, not a downgraded caption.** It renders as a `Pill` (10px medium, toned), not as faint 11px meta text. The fact text and its provenance pill sit on the same top row, pill right-aligned (mirrors the Activity tag placement).

Monospace (`--font-mono`) is reserved for error/failure detail only (matches `PageState` error + `ActivityRowCard` failure line). Never use mono for fact content.

## Color

Inherits the three-theme token system (graphite default / midnight / crimson). Values below are graphite; the surface MUST use the `var(--color-*)` tokens so it themes automatically — never hard-code hex.

| Role | Token (graphite value) | Usage |
|------|------------------------|-------|
| Dominant (60%) | `--color-bg` (#0e0e10) | Page background, scroll area |
| Secondary (30%) | `--color-card` (#1a1a1c) / `--color-elevated` (#222226) | Fact-row cards, Add-fact modal, inline assurance banner |
| Accent (10%) | `--color-accent` (#8b8af0) | See reserved-for list below — nothing else |
| Destructive | `--color-status-failed` (#dc2626) | Delete confirm button + delete-failure text only |

**Accent (`--color-accent`) is reserved for, and ONLY for:**
1. The primary "Add a fact" CTA button (filled accent, white text) — mirrors Activity's "Summarize Today".
2. The active state of a category tab / filter chip (via the established `Tab` active style).
3. The "Confirm" primary action button on an unconfirmed fact row.
4. Focus rings / the Add-fact modal's primary save button.

Accent is NOT used for: provenance tags, the "needs review" marker, row borders, fact text, or generic hover. Hover uses `--color-elevated` / `--color-text` transitions, not accent.

**Provenance tag colors (semantic, theme-agnostic via `Pill` tones — provenance is the hero, so each source reads distinctly but quietly):**
| Provenance | `Pill` tone | Rationale |
|------------|-------------|-----------|
| "You told me" | `accent` (`--color-accent-soft` bg) | Operator-authored = highest-trust; the one place provenance may borrow accent because it signals "your own words". |
| "Learned from your work" | `neutral` (`--color-elevated` / muted text) | Inferred = quiet, not alarming. |
| "Learned from email" | `neutral` | Same; rendered ONLY if an email source exists in data (D-05). |
| "Needs review" marker | `medium` (amber, `--color-priority-medium`) | Unconfirmed inferred fact awaiting operator confirmation (D-04). |

> Note: provenance "You told me" using the `accent` Pill tone is a deliberate, bounded exception to the 10% rule — `accent-soft` is a 12%-opacity tint, not the solid accent, and it is the single trust-defining signal of this surface. It does not count against the solid-accent reserved list above.

## Visual Hierarchy

**Primary visual anchor:** the provenance `Pill` on each fact row. This surface exists to make provenance legible (success criterion 2, CONTEXT §specifics "provenance is the hero"), so the pill is the first thing the eye should catch on every row — right-aligned on the fact's top line, toned per source, never a faint caption. The `Add a fact` accent CTA in the header is the secondary anchor (the one filled-accent element on the page); the category section labels organize the scroll but recede (10px faint uppercase). Everything else — fact text, meta line, row actions — is quiet by design so the provenance signal and the single CTA carry the page.

## Copywriting Contract

All copy follows the project voice (CLAUDE.md): plain, grounded, no em dashes, no AI clichés, honest about coverage. Header direction is locked by CONTEXT.md §specifics.

| Element | Copy |
|---------|------|
| Page title | `What I know about you` |
| Page subtitle (header action slot, muted) | `Stored on this machine. Edit or delete anything.` (the prominent local-storage assurance — success criterion 4) |
| Primary CTA | `Add a fact` |
| Category tab labels | `Your business` · `Your clients` · `How you like to work` (empty categories hidden — D-07) |
| Provenance tags | `You told me` / `Learned from your work` / `Learned from email` (D-03) |
| Unconfirmed marker | `Needs review` (D-04) |
| Row actions (confirmed fact) | `Edit` · `Delete` |
| Row actions (unconfirmed fact) | `Confirm` · `Edit` · `Delete` (D-04) |
| Empty state heading | `Nothing here yet` |
| Empty state body | `As you work together, what the assistant learns about you will show up here, grouped by topic. You can also add a fact yourself. Everything stays on this machine.` |
| Add-fact modal title | `Add a fact` |
| Add-fact assurance (inside modal, near save) | `Stored on this machine. You can edit or delete it anytime.` |
| Add-fact category field label | `Which area?` (operator picks: Your business / Your clients / How you like to work) |
| Add-fact save button | `Save fact` |
| Error state | Reuse `PageState` error: heading `Failed to load`, body = verbatim server reason (no generic wording). |
| Edit-save failure (toast) | `Could not save` + verbatim server reason. |
| Confirm-fact success (toast) | `Confirmed. This fact can now inform what the team does on its own.` |

**Destructive action — Delete a fact (`ConfirmModal`, `destructive`):**
| Field | Copy |
|-------|------|
| title | `Delete this fact?` |
| body | `The assistant will forget this, and it will not be learned again from your work or email.` (states the tombstone guarantee — D-08, success criterion 3) |
| confirmLabel | `Delete` |
| cancelLabel | `Cancel` |
| success toast | `Deleted. It will not come back.` |
| failure toast | `Could not delete` + verbatim server reason. |

There is exactly one destructive action this phase: **Delete a fact.** Edit, Add, and Confirm are non-destructive (no confirmation modal; inline or modal save).

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| View facts | Grouped by category (D-06/D-07). Empty categories are not rendered. Each row: fact text + provenance pill (top row), meta line below. |
| Provenance display | Always present on every row as a `Pill`. "Learned from email" pill renders only when an email-sourced fact exists (D-05 honest coverage). |
| Unconfirmed fact | Shows `Needs review` (amber) marker. Carries `Confirm` / `Edit` / `Delete`. Visually distinct but NOT alarming (quiet card, amber pill only). |
| Edit | In place. Open an inline editor or `Modal` with the fact text + category; `Save fact` persists; failure surfaces verbatim reason via toast. |
| Delete | `ConfirmModal` (destructive). On confirm, writes a tombstone (D-08) so the fact is not silently re-derived. Success/failure via toast. |
| Confirm (unconfirmed only) | One action; promotes the fact to confirmed so it may inform Permissions/behavior (D-04). No modal; toast on success. |
| Add a fact | Accent CTA in `PageHeader` action slot opens `Modal`: fact text field + category picker + the local-storage assurance line + `Save fact`. Inserts a confirmed, operator-authored "You told me" fact (D-09). |
| Loading / error / empty | Always via `PageState` (never hand-rolled). |
| Action affordances | Buttons that cannot act are ABSENT, never disabled-and-dead (matches Activity's Undo rule). E.g. `Confirm` appears only on unconfirmed rows. |
