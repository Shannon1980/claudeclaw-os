re-derived" guarantee (success criterion 3) with an automated test proving suppression. After this plan
the operator can fully manage facts; the cross-cutting behavior gate + categorization engine work
follows in Plan 04.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> mutation routes (POST/PATCH/DELETE) | untrusted operator input (summary, category, id) crosses here |
| delete -> ingest/consolidate | a deleted fact must not be re-derivable by the engine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Tampering | SQL injection via summary/category in new mutations | mitigate | All SQL in db.ts bound via ? placeholders; never interpolate summary/category (house rule, RESEARCH V5) |
| T-06-07 | Spoofing/Tampering | CSRF on new POST/PATCH/DELETE | mitigate | Inherited Origin allowlist middleware (dashboard.ts:495); no per-route code |
| T-06-08 | Tampering | mutation during incident | mitigate | Inherited DASHBOARD_MUTATIONS_ENABLED 503 kill switch (dashboard.ts:449) |
| T-06-09 | Tampering | tombstone evasion (deleted fact re-derived) | mitigate | HIGH: tombstone written BEFORE row delete (fail-safe), hash floor is deterministic + always-on, embedding secondary at 0.88; checked at BOTH ingest dedupe point and pre-consolidation save; automated suppression test proves it |
| T-06-10 | Elevation of Privilege | category accepted outside the 3-value enum | mitigate | Validate category against {your-business, your-clients, how-you-work} on Add/Edit; reject otherwise |
| T-06-11 | Tampering | confirm double-fire | mitigate | Status-guard the confirm transition; .changes===0 is an honest no-op |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs this phase (RESEARCH: zero external packages) |
</threat_model>
