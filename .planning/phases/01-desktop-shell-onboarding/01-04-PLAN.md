<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build machine -> end-user machine | The .dmg crosses to untrusted machines; Gatekeeper is the trust check |
| notary creds in env | App-specific password / cert password are secrets in the build env |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering / Spoofing | unsigned .dmg | mitigate | Developer ID sign + hardened runtime + notarize + staple; Gatekeeper validates on the clean machine |
| T-04-02 | Information Disclosure | notary creds in CI/env | mitigate | Creds read from env only at build time; notarize.cjs no-ops (does not echo) when absent; never committed |
| T-04-03 | Elevation of Privilege | hardened-runtime entitlements | accept | allow-jit / allow-unsigned-executable-memory are required for Electron + spawning node/claude; scoped to the minimum Electron needs |
| T-04-SC | Tampering | @electron/notarize install | mitigate | Blocking package-legitimacy checkpoint (task 3) verifies the official Electron-org package before it stays installed |
</threat_model>
