<objective>
Replace the two broken onboarding mechanisms with the verified-correct ones and wire auth precedence to the tested helper, then prove a real authenticated SDK round-trip and confirm login-item persistence. Swap the deprecated `npm i -g @anthropic-ai/claude-code` install for the native installer, swap interactive `claude login` + the ~/.claude filesystem heuristic for `claude setup-token` capture (mechanism per plan 01's A1 outcome), route every auth write through src/desktop-config.resolveAuthWrite (consumed from CommonJS via the compiled dist output) so OAuth and an API key can never coexist, add a queryable active-auth-source for Settings > Account (D1), and verify the captured credential actually authenticates a spawned `claude` subprocess.

Output: hardened install/login/auth IPC + onboarding UI, active-source readout, a real SDK auth round-trip check, confirmed login-item registration.
</objective>

| renderer wizard -> main IPC | Untrusted user input (API key, tokens) crosses into privileged file writes |

| main -> claude (verifyAuth round-trip) | Spawns the CLI with the scrubbed SDK env to prove auth; token must not leak to logs |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
