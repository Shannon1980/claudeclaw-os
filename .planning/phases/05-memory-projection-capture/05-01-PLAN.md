<design_notes>
- **Unified pool key (locked decision 1).** Derive deterministically from the agent id: `workspaceMemoryKey(agentId)` returns `ws:${agentId}` (so `ws:aos`). `isWorkspaceAgent(agentId)` is true when `loadAgentConfig(agentId).projectDir` is set and exists (same predicate `resolveAgentRuntime` uses). All three consumers (delegation save, delegation recall, projection, capture) call `workspaceMemoryKey` so they agree on one chat_id. Non-workspace agents and the main path are NOT rerouted (COMPAT-02).
- **MEM-06 (locked decision 3).** Projection reads ONLY `getRecentHighImportanceMemories` / `getRecentMemories` from `db.ts`. Never open the sqlite file from a new connection, never call `decryptField`, never read `wa_*`/`slack_messages`.
- **Separate file (locked decision 4).** Projection writes `context/memory/{YYYY-MM-DD}.claudeclaw.md`; it must never touch `{date}.md`.
- **No schema change (locked decision 5).** Reuse `source` + `session_id` for dedup. If a column turns out to be genuinely required, STOP and use the `add-migration` skill — do not hand-edit.
- **hooks.ts stays unwired (locked decision 2).** Roadmap success criterion 4 ("hooks not dead code") is satisfied by the agentic-os Stop hook firing (Plan 02), NOT by wiring `src/hooks.ts`. State this reinterpretation in the SUMMARY.
- No em dashes in any text the projection injects into the workspace file (CLAUDE.md rule).
</design_notes>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| terminal Claude Code Stop hook -> capture-cli | A separate-process CLI receives JSON on stdin authored by an agent's session; untrusted input crosses into ClaudeClaw's DB write path |
| capture-cli process -> store/claudeclaw.db | A foreign-cwd process writes to the single source-of-record store while the bot may hold it (WAL) |
| memory rows -> workspace markdown file | Memory summaries are written into an external workspace file a terminal session reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering / DoS | capture-cli stdin JSON | mitigate | `JSON.parse` in try/catch (exit 0 on failure); length-cap captured text at 4000 chars; `setTimeout(...4000)` stdin safety net (Task 3) |
| T-05-02 | Information Disclosure | memory-projection output | mitigate | Project only `summary` from `memories` (plaintext); never read `wa_*`/`slack_messages`; never call `decryptField`; source-guard test asserts absence (Task 2) |
| T-05-03 | Information Disclosure | wrong/encrypted table read | mitigate | Hard rule: projection reads ONLY via `getRecentHighImportanceMemories`/`getRecentMemories`; MEM-06 source-guard test (Task 2) |
| T-05-04 | DoS | feedback-loop amplification (projection re-captured) | mitigate | session_id + content dedup guard in capture (Task 3) + existing 0.85 cosine dedup; markdown strictly one-directional out |
| T-05-05 | Tampering | path traversal via resolved workspace path | mitigate | Write a fixed filename under `resolveAgentRuntime` cwd + `existsSync` guard on `context/memory/`; never use a hook-supplied path for the write target (Task 2) |
| T-05-06 | Elevation/Access Control | capture writing under a foreign agent_id | mitigate | Attribution is server-side fixed to `'aos'` + `workspaceMemoryKey('aos')`, never taken from stdin (Task 3) |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase (RESEARCH Package Legitimacy Audit: not applicable). No `[ASSUMED]`/`[SUS]` packages. |
</threat_model>
