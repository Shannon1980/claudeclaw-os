<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/audit, /api/audit/export | Untrusted query params (search/type/dates/format/token) cross into the DB read and the export |
| exported CSV → spreadsheet app | A cell could execute as a formula when opened in Excel |
| export URL → browser history / Referer | The token rides in the URL for the GET download |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05 | Tampering | /api/audit + export filter params | mitigate | All filters bind via better-sqlite3 `?` placeholders; validate format ∈ {csv,json}; clamp/parse dates as integers (ASVS V5) |
| T-05-06 | Tampering/Code-exec | CSV export opened in Excel | mitigate | toCsv prefixes leading `= + - @` with `'` and applies RFC-4180 quoting; unit-tested |
| T-05-07 | Elevation/Spoofing | /api/audit/export access | mitigate | Mounted under /api/ for the existing token middleware; no public path; GET mutations-exempt by design |
| T-05-08 | Information Disclosure | export token in URL history | accept | Referrer-Policy: no-referrer already set (:281); token-in-URL is required for browser download GET (A6); fetch→blob is a future hardening if history retention becomes a concern |
| T-05-09 | Tampering | audit_log via read/export path | mitigate | Read/export are SELECT-only; zero UPDATE/DELETE on audit_log (append-only hard rule) |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed this phase; no Package Legitimacy Gate applies |
</threat_model>
