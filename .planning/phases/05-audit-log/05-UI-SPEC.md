# Phase 5 — UI Design Contract

> Visual and interaction contract for the admin-facing Audit log surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **The one rule that overrides every other choice here:** Audit is the *dense, technical* back half of the trust chain. It must look deliberately UNLIKE the operator-facing Activity feed (Phase 4). Activity = soft card/list, plain language, sentence-case phrases, no monospace. Audit = monospace timestamps + detail, tabular rows, technical event-type tags. "Two screens, deliberately different." Do NOT inherit `Activity.tsx`'s card anatomy.

---

## Design System

The project has an established Preact dashboard design system (CSS-variable tokens in `web/src/styles/main.css`, shared primitives in `web/src/components/`). It is NOT a React/Next/Vite + shadcn project — the renderer is **Preact 10** with **Tailwind CSS v4** (`@theme inline` token bridge). The shadcn initialization gate does not apply: a design system already exists and shadcn is not compatible with this stack. This phase **inherits** that system; it does not introduce a new one.

| Property | Value |
|----------|-------|
| Tool | none (inherit existing Preact/Tailwind v4 system) |
| Preset | not applicable |
| Component library | none (hand-rolled primitives: `PageHeader`/`Tab`, `PageState`, `Pill`/`StatusDot`, `ConfirmModal`/`Modal`, `Toggle`, `AgentAvatar`) |
| Icon library | `lucide-preact` 1.14.0 |
| Font (sans) | Inter — `var(--font-sans)`, body copy, labels, headers |
| Font (mono) | **JetBrains Mono** — `var(--font-mono)`, the load-bearing "this is technical" signal: timestamps, tool/target/session/model, detail JSON, event-type tags |

**Reuse, do not re-specify:** `PageHeader` + `Tab`, `PageState` (loading/error/empty), `Pill` + `StatusDot` (tones), `ConfirmModal`, `AgentAvatar`, `teammateColor()`, `formatCost`/`formatDuration` from `lib/format.ts`. New work is additive: a dense table row with an expand-for-detail disclosure, a filter bar, an Export control, a retention/coverage banner.

## Spacing Scale

Tailwind v4 default scale (4px base). Audit is **denser** than Activity by design — rows use compact vertical padding; the body table is the focal density signal.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline tag padding (`gap-1`, `py-0.5`) |
| sm | 8px | Cell padding within a row, chip spacing (`py-2`, `gap-2`) |
| md | 16px | Filter-bar internal grouping, banner padding, expanded-detail block vertical padding (`gap-4`, `p-4`, `py-4`) |
| lg | 24px | Page horizontal gutter aligns to existing `px-6` (24px) |
| xl | 32px | Expanded-detail block internal section gaps |
| 2xl | 48px | (not used this phase) |
| 3xl | 64px | (not used this phase) |

**Row density rule:** log rows use `px-6 py-2` (24px horizontal to match the page gutter, 8px vertical for density). Expanded detail uses `py-4` (16px) and a top border to separate it from the row — `py-4` gives the dense key/value grid a little breathing room as a distinct block while staying on the declared scale (the bare row stays tight at `py-2`). Do NOT widen rows to Activity's `p-3` card spacing — density is the contract.

Exceptions: none.

## Typography

Audit leans on TWO type families to do its job: Inter for headers/labels, JetBrains Mono for every machine value. Sizes match the existing dense dashboard scale; weights stay at the two the system already uses.

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Page title ("Audit log") | 14px | 600 (semibold) | 1.2 | Inter |
| Body / row description | 12px | 400 (regular) | 1.5 | Inter |
| Column header + section label | 10px | 600 (semibold) | 1.2, uppercase, `tracking-wider` | Inter |
| Machine values (timestamp, tool, target, session, model, detail) | 11px | 400 (regular) | 1.5 | **JetBrains Mono** |

- **Exactly two weights: 400 (regular) and 600 (semibold).** The system never goes heavier than semibold; emphasis (page title, column headers, section labels) is carried by **600**, everything else by **400**. No 500/medium anywhere.
- **3 sizes (14 / 12 / 11) + the 10px uppercase micro-label** matching the existing `.section-label` convention.
- **The 10/11/12px cluster is intentionally tight — do NOT "fix" it by bumping sizes.** Each role is differentiated not by point size but by **family** (Inter vs JetBrains Mono) and **treatment** (uppercase + `tracking-wider` for the 10px label, `tabular-nums` for mono values). Pulling these sizes apart would weaken the technical density that is this surface's whole point.
- **Monospace is reserved and meaningful.** Any value that is a machine fact (precise timestamp, tool name, target id, session id, model, cost, duration, raw detail) renders in JetBrains Mono. Human prose (the plain-language description, banner copy, empty/error states) stays in Inter. This split IS the "technical vs. operator" signal — keep it strict.
- Timestamps use `tabular-nums` and render **precise to the second** in local time (e.g. `2026-06-25 14:32:07`), NOT the relative "5m ago" the current `Audit.tsx` uses. Relative time is an Activity affordance; absolute monospace time is an Audit affordance.

## Color

Inherit the three dark themes (graphite default, midnight, crimson) via CSS variables — never hardcode. Dark mode is mandatory (foundations). The 60/30/10 split maps onto existing tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` (#0e0e10 graphite) | Page background, table body, sticky header row backing |
| Secondary (30%) | `var(--color-elevated)` / `var(--color-card)` | Filter bar, expanded-detail block, row hover (`hover:bg-[var(--color-elevated)]`), banner |
| Accent (10%) | `var(--color-accent)` (#8b8af0 graphite) | **Reserved list below — never "all interactive elements"** |
| Destructive | `var(--color-status-failed)` (#dc2626) | Error outcome icon/tag only; there are no destructive *actions* this phase (the log is append-only, read-only) |

**Accent (`--color-accent`) is reserved for, and ONLY for:**
1. The active state of a filter chip / type chip (selected = `bg-[var(--color-elevated)]` per existing `Tab`; accent is NOT used for chip selection — chips follow the existing neutral `Tab` pattern). *Accent is reserved exclusively for #2 below.*
2. The primary **Export log** button fill (`bg-[var(--color-accent)] text-white hover:bg-[var(--color-accent-hover)]`), matching the single primary-action treatment used by Activity's "Summarize Today".

That is the entire accent surface this phase. Everything else (links, hover, focus rings on neutral controls) uses muted/text tokens, exactly as the existing surfaces do.

**Outcome icon + event-type tag color language (theme-agnostic status tokens — constant across themes for universal recognition):**

| Outcome | Token | Icon (lucide) | Reads as |
|---------|-------|---------------|----------|
| ok / allowed | `--color-status-done` (#16a34a green) | `ShieldCheck` / `Check` | succeeded |
| held / queued / needs-approval | `--color-priority-medium` (#ca8a04 amber) | `Clock` / `PauseCircle` | parked at a permission boundary (the system working) |
| error / blocked / denied | `--color-status-failed` (#dc2626 red) | `ShieldAlert` / `XCircle` | failed or refused |

**Event-type tag tones** (the chip on each row — distinct neutral-leaning palette so type and outcome don't fight): render event-type tags as **monospace, low-chroma `Pill tone="neutral"`** with the type word (`action` / `permission` / `auth` / `routine` / `config` / `error`). The `error` type may use `tone="failed"`. Type ≠ outcome: a `permission` event can have a `held` outcome; show both. Keep type tags quiet so the outcome icon stays the row's strongest signal.

**Actor badge** reuses `teammateColor()` for teammates (fixed per-teammate accent — Research purple, Comms teal, Content coral, Ops amber, Assistant gray); `System` and `You` use neutral `--color-text-muted` with a distinct glyph so they are never mistaken for a teammate color.

## Copywriting Contract

All copy: sentence case, no em dashes, no AI clichés, honest about coverage. "Complete, read-only" is a promise — never imply coverage that isn't captured (success criterion 2, verbatim).

| Element | Copy |
|---------|------|
| Page title | `Audit log` |
| Page subtitle | `Complete, read-only record of every event` |
| Retention line (always visible, beside/under subtitle) | `Retaining {N} days` (default 90; the number MUST be the configured value, never hardcoded in copy) |
| Primary CTA | **Export log** (button label `Export log`; on click reveals format choice — see interaction notes) |
| Export format choices | `Export as CSV` · `Export as JSON` |
| Export scope reassurance (near the control) | `Exports every event matching your current filters, not just what is on screen.` |
| Coverage-honesty banner (when a category is not yet captured) | `Not yet captured: {category list}. These events are not recorded yet, so this log does not claim to cover them.` |
| Type chip — not-yet-captured state | A type with no backing data is shown **disabled with a footnote** reading `not yet captured`, never as an active-looking empty filter. |
| Empty state heading (no events at all) | `No events recorded yet` |
| Empty state body | `Every action, permission decision, auth event, routine run, and error will appear here as it happens. This log is append-only and is never edited or trimmed.` |
| Empty state body (filtered to zero) | `No events match these filters. Clear the search, type, or date range to see the full record.` |
| Error state | `Could not load the audit log. {verbatim server reason}. The log itself is unaffected; this is a display problem.` |
| Export failure toast | `Could not export. {verbatim server reason}.` |
| Destructive confirmation | **None.** The log is append-only and read-only — there is no delete, no edit, no clear, no destructive action anywhere on this surface. The absence is the contract. |

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Row expand | Click the row (or a Detail chevron) toggles a single open row at a time, mirroring Activity's `openRow` single-open model. Expanded detail shows the full technical key/value grid in a `py-4` block with a top border. |
| Honest detail | Every field that was not captured for that event renders the literal token `not captured` in faint text. The UI never shows an empty cell that could imply "no value" vs "not recorded". |
| Type chip (has data) | Toggles a server-side filter; combines with search + date range (AND). Active chip uses the existing `Tab` selected style. |
| Type chip (no data) | Disabled, non-interactive, carries the `not yet captured` footnote. It is visible (so the operator knows the type exists in the spec) but cannot be selected and never implies coverage. |
| Search | Debounced text filter applied server-side across description/tool/target/detail; combines with chips + date range. |
| Date range | Filters the loaded set and, critically, the **Export** scope. |
| Export | The `Export log` button reveals CSV/JSON choice; downloads the **complete filtered set** (never page-capped). Same token gate + mutations behavior as other `/api/*` routes. Busy → both options disabled; failure → honest toast. |
| Delete / edit / clear | **Not present.** No affordance exists to mutate the log. |

## Placement / Navigation (D-13)

The Audit surface relocates **out of the operator's main intelligence nav** and **under Settings > Security / admin**. It is opened deliberately, not glanced at daily.

- Remove (or demote) the top-level `/audit` entry from the main `ROUTES` intelligence section in `web/src/lib/routes.ts` (Phase 4 created `nav.audit` for exactly this demotion).
- Surface it as a **Security / admin section inside `Settings.tsx`** (the page already composes `<Section>` blocks: Permissions, Workspace, Display, Read-only, Acknowledgements). Add a `Security` section that links to / hosts the Audit surface.
- Keep the route reachable (the page still exists at its path for deep-linking and the command palette), but it is no longer a primary sidebar item. The exact route string + `vocabKey` grouping under Settings is the planner's call (CONTEXT Claude's-discretion), but it MUST land under the Settings/Security grouping, not the daily-path nav.
- `vocabKey`: keep `nav.audit` / `page.audit` (`Audit` in both operator and builder modes); the term itself does not change, only its placement.
