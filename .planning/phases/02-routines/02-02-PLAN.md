## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored step action text → teammate SDK subprocess | Operator-authored step prompts run as a teammate via delegateToAgent (untrusted-ish prompt crosses into an LLM with that teammate's tools) |
| in-memory test DB / production DB → schema migration | The live scheduled_tasks table gains a column + two companion tables |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02 | Elevation of Privilege | Prompt injection via step.action running under a teammate's tools | mitigate (this phase) / defer enforcement | delegateToAgent already runs with getScrubbedSdkEnv (secrets stripped from subprocess); stored autonomy is NOT enforced here and MUST NOT be surfaced as a security guarantee (D-08 honesty). Real per-action gating is Phase 3. |
| T-02-03 | Tampering | SQL injection via step action / routine name | mitigate | All routine CRUD uses parameterized better-sqlite3 prepared statements; never string-concat user text into SQL (codebase universal pattern) |
| T-02-04 | Tampering | Cross-process / double-execution of a routine | mitigate | claimDueTask atomic UPDATE ... WHERE status='active' claims exactly once per run (not per step) + runningTaskIds in-memory guard; routine row owned by agent_id='main' so the single main loop fires it (A1) |
| T-02-05 | Denial of Service | A stuck step hanging the runner | mitigate | delegateToAgent invoked with TASK_TIMEOUT_MS bound, mirroring the mission/aos-cron path |
| T-02-06 | Tampering | Migration column-parity drift → crash-loop | mitigate | Dual-write: addColumnIfMissing in runMigrations AND versioned migrations/v1.2.2 file + version.json bump; run npm run migrate before restart (CLAUDE.md) |
