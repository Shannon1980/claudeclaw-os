# Phase 2 — UI Design Contract: Routines

> Visual and interaction contract for the Routines surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is NOT a greenfield UI.** The dashboard already exists (Preact + Vite + Tailwind v4, single token sheet at `web/src/styles/main.css`). This contract ALIGNS to that system — it does not introduce a new one. shadcn is intentionally **not applicable**: the project uses a hand-rolled CSS-variable token system with three dark themes (graphite/midnight/crimson) and Tailwind v4 `@theme inline` utilities. Introducing shadcn/Radix would fork the design language. The new `web/src/pages/Routines.tsx` reuses existing components and the same `var(--color-*)` tokens.

## Spacing Scale

The existing dashboard is **dense** (13px base, compact padding). Match it — do not introduce a roomier 8-point rhythm that visually clashes with Scheduled/Team. Declared values (multiples of 4, expressed via Tailwind utilities the codebase already uses):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), pill padding |
| sm | 8px | Inter-element spacing in a row (`gap-2`), card inner padding (`p-2`) |
| md | 12px | Card padding (`p-3`), row vertical rhythm (existing cards use `p-3`) |
| lg | 16px | Detail-section gaps (`space-y-4` content blocks) |
| xl | 24px | Page content padding (`p-6` — matches Scheduled.tsx list/card container) |
| 2xl | 32px | Major break between builder panel and list |
| 3xl | 48px+ | Empty-state vertical centering (`py-16` via `PageState`) |

Exceptions:
- On/off `Toggle` uses `size="sm"` (32×18px track) per the existing component — this is the established control size, not a spacing violation.
- Teammate `AgentAvatar` on steps: 18–20px (sub-md) to keep the ordered step list compact; matches inline-identity sizing elsewhere.
- Touch targets: this is a desktop Electron app (mouse/trackpad), so existing 28–30px icon-button hit areas (`p-1.5`) are retained rather than forcing 44px.

## Typography

The system base is **13px / line-height 1.5 / Inter**. The type scale is small and dense; match it exactly. Three sizes + one uppercase-label treatment (matching `.section-label`), two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Heading (page title) | 14px | 600 (semibold) | 1.4 (`PageHeader` default) |
| Body / routine name / step action | 12.5px | 500 (medium) for names, 400 for body text | 1.5 |
| Meta / schedule / count line / timestamps | 11px–11.5px | 400 | 1.5 |
| Section label (uppercase) | 10px | 500 | 1.5, `letter-spacing: 0.08em`, `text-transform: uppercase`, `--color-text-faint` (the `.section-label` helper / pattern used in ScheduleBuilder) |

Weights: exactly **two tiers** — `400` (regular body) and a single **emphasis tier** that is `500` everywhere except the `PageHeader` title, which keeps its existing `600`. Treat `500`/`600` as one emphasis tier; do NOT introduce a third visual weight level. The system never uses bold beyond 600. Numerals in schedule/countdown/timestamps use `tabular-nums` (existing convention).
Mono (`--font-mono`, ~11px) is reserved for the raw-cron escape hatch and raw run output only — never for operator-facing schedule or copy.

## Color

The palette is theme-driven (graphite default + midnight + crimson). **Reference the CSS variables — never hardcode hex for surfaces or accent.** Status colors are theme-agnostic constants (defined in `:root`) and ARE referenced by variable. The 60/30/10 split maps to the existing token tiers:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` (#0e0e10 graphite) | Page background, scroll containers |
| Secondary (30%) | `var(--color-card)` / `var(--color-elevated)` (#1a1a1c / #222226) | Routine rows, detail panel, builder panel, step cards |
| Accent (10%) | `var(--color-accent)` (#8b8af0 graphite; theme-dependent) | See reserved list below |
| Destructive | `var(--color-status-failed)` (#dc2626) | Delete routine, failed run outcome |

Accent reserved for (explicit — never "all interactive elements"):
- The **on** state of the routine `Toggle` (it already binds `--color-accent`).
- The **"New routine"** primary button and the builder's **"Save routine"** confirm button.
- Active selection in the `AutonomySelector` and `ScheduleBuilder` day/time pickers (existing pattern: active = `bg-[var(--color-accent)] text-white`).
- The **countdown to next run** ("in 3h") text, matching Scheduled.tsx.
- Focus rings (`focus-visible:ring-[var(--color-accent)]`).
Accent is NOT used for: routine names, body text, run-outcome chips, teammate tags, or row hover (hover uses `--color-border-strong` / `--color-elevated`).

**Run-outcome colors (theme-agnostic status tokens — the core RTN-05 contract):**

| Outcome | Token | Icon (`lucide-preact`) | Pill tone |
|---------|-------|------------------------|-----------|
| ok | `var(--color-status-done)` #16a34a | `Check` / `CheckCircle2` | `done` |
| degraded | `var(--color-status-running)` #d97706 (amber) | `AlertTriangle` | `medium` |
| failed | `var(--color-status-failed)` #dc2626 (red) | `XCircle` | `failed` |

**Teammate tag colors (fixed, from `teammateColor()` in Team.tsx — reuse that function, do not redefine):** Research `#a78bfa`, Comms `#2dd4bf`, Content `#fb7185`, Ops `#f59e0b`, fallback `var(--color-accent)`. Rendered as a soft chip: `color-mix(in srgb, {color} 18%, transparent)` background + `{color}` text + the teammate `AgentAvatar`, matching the `Pill` tone construction.

**Off (paused) routines:** visually dimmed via opacity (`opacity-50` on the row content, NOT a color change) so the row reads as muted without inventing a new gray — matches the spec's "off routines are visually dimmed" and the non-destructive pause model.

## Component / Interaction Contracts

### 1. List view (`Routines.tsx` + `RoutineRow`)
- `PageHeader` title `term('page.routines')` ("Routines"). Actions slot: count line + "New routine" button.
- **Count line** (right-aligned meta, 11.5px muted, `tabular-nums`): `"{onCount} on, {offCount} off"` (e.g. "3 on, 1 off"). Copy is Claude's discretion per CONTEXT but MUST state on/off split, not a raw total.
- **"New routine" button:** accent primary, opens the embedded builder panel (does NOT navigate to Chat).
- **Each `RoutineRow`** (model on the Scheduled.tsx card, restyled to spec anatomy):
  - icon + name (12.5px medium); plain-language schedule via `describeCron(...).text` with a `Clock` icon (10px) — **never raw cron**;
  - step count + last/next run meta: `"{n} steps · ran today, 8:00am"` (next-run countdown in accent when on);
  - `RunOutcomeBadge` for the most recent run (Pill, see colors above);
  - on/off `Toggle` (`size="sm"`) — **primary, non-destructive control**, no confirm modal;
  - expand affordance (chevron) → `RoutineDetail` inline.
  - Off routines: row content `opacity-50`; the toggle itself stays full-opacity so it is clearly re-enableable.

### 2. Expanded detail (`RoutineDetail`)
Four blocks, each led by a `.section-label`-style uppercase header:
- **When:** plain-language schedule + a "Change" text-action that opens the existing `ScheduleBuilder`. The raw-cron escape hatch lives **inside `ScheduleBuilder`'s "Advanced (cron)" toggle** (already built, never default). Operator path stays plain-language.
- **Steps:** ordered `StepList`. Each `StepRow` = step number + action text + `TeammateTag` (colored chip + avatar). Add-step and reorder affordances (drag handle or up/down — Claude's discretion). A step whose teammate is paused shows a muted "teammate paused" note (Team↔Routines link).
- **Recent runs:** list of `RunHistoryItem` = `RunOutcomeBadge` + timestamp (`formatRelativeTime`) + "View output". Failures shown **honestly and verbatim** (e.g. "calendar not connected, sent partial") — never collapsed to a generic "error". Degraded is visible, not hidden.
- **Actions:** "Run now" (secondary) and "Turn off" (mirrors the row toggle). "Run now" fires `pushToast` "Run started" on success.

### 3. Embedded conversational builder (`RoutineBuilderPanel`) — D-04 / D-05
- A **panel ON the Routines page** (slides in / expands above the list), NOT a hand-off to the Chat surface. Operator stays on the page.
- Seed prompt direction (assistant-initiated): "Help me build a new routine. Ask me what should happen and when, then turn it into steps I can review."
- **Draft-first / nothing persists until confirm:** assistant proposes (a) a schedule and (b) an ordered step list, rendered as an **editable draft** using the SAME `StepList`/`ScheduleBuilder` surfaces as detail. The draft is visually marked (e.g. a "Draft — not saved yet" `Pill` tone `accent` / dashed border) so the operator knows nothing is live.
- Operator can edit step text, reassign teammates, reorder, add/remove steps, and adjust the schedule **before** anything saves.
- Confirm = "Save routine" (accent). Cancel/discard a dirty draft routes through `ConfirmModal` (destructive: "Discard this draft?") so typed steps aren't lost on a stray click.

### 4. At-creation autonomy selector (`AutonomySelector`) — D-07
- **Visible at creation inside the builder, above "Save routine"** — a deliberate, non-buried control (routines run while the operator sleeps).
- Two-option segmented control (existing active-segment pattern: `bg-[var(--color-accent)] text-white` for the chosen option):
  - **"Run unattended"** — draft / prepare / notify only.
  - **"Queue for my approval"** — send / pay / commit actions wait as "Needs you".
- Each option carries a one-line plain explainer (11px muted). The choice is **stored on the routine** and surfaced read-only in `RoutineDetail` (a small `Pill`). This phase PRESENTS + STORES only; enforcement is Phase 3 (do not build the gate). Keep the stored shape forward-compatible with the Phase 3 four-tier model.

### 5. Run-outcome states — color/icon/copy contract
See the run-outcome color table above. Copy contract:
- **ok:** badge "Ran clean" (or "Success"); no notification (silent on success per D-09).
- **degraded:** badge "Partial" + amber; history shows the honest reason ("calendar not connected, sent partial").
- **failed:** badge "Failed" + red; history shows the failing step + reason.
- **Failure notification (D-09/D-10) is transport, not a screen.** In-app surface: a small failed/degraded indicator on the routine row when its latest run broke (a `RunOutcomeBadge` already covers this). Do not over-spec push UI. Alert fires once on `ok → degraded/failed` state change, not on every subsequent failing run.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "New routine" |
| Count line | "{n} on, {n} off" (e.g. "3 on, 1 off") |
| Empty state heading | "No routines yet" |
| Empty state body | "Routines are work that runs on its own. Describe one in plain language — like 'every weekday at 8, check my calendar and send me a brief' — and your team handles it. Tap New routine to start." |
| Error state | Uses `PageState error` ("Failed to load" + the error string). |
| Run-now toast (success) | "Run started" |
| Save-routine toast (success) | "Routine saved" |
| Degraded history line | Honest reason verbatim, e.g. "Calendar not connected — sent partial brief." |
| Failed history line | "{Step name} failed: {reason}." |
| Discard-draft confirmation | "Discard this draft? Your steps haven't been saved." — confirm label "Discard". |
| Delete-routine confirmation (destructive) | "Delete this routine? It won't run again. Past run history stays." — confirm label "Delete". |
| Autonomy: unattended | "Run unattended — drafts, prepares, and notifies you. Won't send, pay, or commit on its own." |
| Autonomy: queue | "Queue for my approval — actions that send, pay, or commit wait for you as a Needs-you item." |
| Turn-off (toggle, no modal) | non-destructive; no confirmation. Tooltip "Turn off" / "Turn on". |

Voice: plain operator language, no cron, no "agent"/"task" (use teammate/routine via `term()`). No em dashes in shipped copy (project rule) — use commas or "—" only where it reads as a dash in the spec examples; shipped strings should prefer commas/periods.
