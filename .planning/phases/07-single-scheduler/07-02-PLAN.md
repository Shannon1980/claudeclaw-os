<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workspace .md files → DB rows | arbitrary prompt + schedule strings from `cron/jobs/*.md` are read into scheduled_tasks |
| cron string → computeNextRun | a malformed `time`/`days`/`cron:` could throw and abort sync |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03 | Tampering / Elevation | prompt body sourced from `cron/jobs/*.md` | accept | The `.md` files are the user's own workspace source of truth (already trusted to run as the user in agentic-os today); ClaudeClaw treats them as a derived projection and runs them as the scoped `aos` agent. No new trust surface vs. the retired engine; documented as the source of truth in SCHEDULER-HANDOFF.md. |
| T-07-04 | Denial of Service | malformed schedule string aborts sync | mitigate | `toCron` validates against `CronExpressionParser.parse`; sync wraps per-file parse/map in try/catch so one bad job file logs + skips rather than aborting the whole sync. |
| T-07-05 | Tampering | sync writing back to `.md` files | mitigate | Sync is strictly read-only on the filesystem (fs.readdirSync/readFileSync only); DB rows are the projection. Asserted by acceptance criterion. |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages (uses existing `js-yaml`, `cron-parser`). No legitimacy checkpoint required. |
</threat_model>
