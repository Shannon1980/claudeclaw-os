# Phase 3 — UI Design Contract: Permissions & Autonomy

> Visual and interaction contract for the Permissions & Autonomy surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is NOT a greenfield UI.** Same resolution as Phase 2: the dashboard already exists (Preact + Vite + Tailwind v4, single token sheet at `web/src/styles/main.css`, three dark themes graphite/midnight/crimson). This phase ADDS a **Permissions section to the existing `web/src/pages/Settings.tsx`** and a **minimal gated-action approval surface to the existing `web/src/pages/Home.tsx`**. It introduces NO new design system. shadcn is intentionally **not applicable** — introducing shadcn/Radix would fork the hand-rolled `var(--color-*)` token language. All new components reuse the same tokens and the Settings `Section`/`Card`/`Row`/`Divider`/`ReadOnlyRow` primitives and the `Toggle`/`Pill`/`ConfirmModal`/`AgentAvatar` components.
>
> **Spec anchors:** `specs/operator-product/07-permissions-settings.md` (the dial, four-tier model, locked Tier 4, "Ask first is cheap"), `specs/operator-product/03-home.md` ("Needs you"). CONTEXT decisions D-01..D-11 are LOCKED and pre-populate this contract.

## Spacing Scale

The dashboard is **dense** (13px base, compact padding). Match it exactly — do not introduce a roomier rhythm that clashes with Settings/Home. Declared values (multiples of 4, expressed via Tailwind utilities the codebase already uses):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), pill padding, lock-icon spacing |
| sm | 8px | Inter-element spacing in a row (`gap-2`), segmented-control inner gap |
| md | 12px | Approval-item padding (`p-3`), override-row vertical rhythm |
| lg | 16px | Card padding (`p-4` — matches Settings `Card`), section-internal gaps |
| xl | 20–24px | Between Settings sections (`space-y-5` — matches Settings page), page content padding (`px-6`) |
| 2xl | 32px | Major break between the mode dial and the override list |
| 3xl | 48px+ | Empty-state vertical centering (`py-4`–`py-16` via `PageState`/inline empty) |

Exceptions:
- Mode-selector radio cards are larger touch targets (~`p-3`, min height ~64px) than override rows — deliberate, the dial is the primary control and must read as prominent (spec: "a dial, not a checkbox wall").
- `AgentAvatar` on approval items: 16–18px (sub-md) to keep the Home list compact, matching inline-identity sizing elsewhere.
- Desktop Electron app (mouse/trackpad): existing 28–30px icon-button hit areas (`p-1.5`) are retained for the approve/deny buttons rather than forcing 44px.

## Typography

System base is **13px / line-height 1.5 / Inter**. Match the small, dense scale exactly. Three sizes + one uppercase-label treatment (the existing `.section-label`), two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Heading (section / card title) | 13–14px | 600 (semibold) — matches Settings `Section` `<h2>` and `NeedsYouCard` title | 1.4 |
| Body / mode name / override label / approval summary | 12.5–13px | 500 (medium) for names/mode titles, 400 for body + hints | 1.5 |
| Meta / explainer / timestamp / tier note | 11–11.5px | 400 | 1.5 (`leading-snug`) |
| Section label (uppercase) | 10px | 500 | 1.5, `letter-spacing: 0.08em`, `text-transform: uppercase`, `--color-text-faint` (the existing `.section-label` helper) |

Weights: exactly **two tiers** — `400` (regular body/hints) and a single **emphasis tier** that is `500` everywhere except section/card titles which keep the existing `600`. Treat `500`/`600` as one emphasis tier; do NOT introduce a third visual weight. No bold beyond 600. Numerals in timestamps and the "Needs you" count use `tabular-nums` (existing convention). Mono is NOT used anywhere in the operator permissions path.

## Color

Palette is theme-driven (graphite default #8b8af0 accent + midnight #5eb6ff + crimson #ff5e6e). **Reference the CSS variables — never hardcode hex for surfaces or accent.** Status colors are theme-agnostic constants in `:root` and are referenced by variable. The 60/30/10 split maps to the existing token tiers:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` (#0e0e10 graphite) | Settings/Home page background, scroll containers |
| Secondary (30%) | `var(--color-card)` / `var(--color-elevated)` (#1a1a1c / #222226) | The Permissions Card, override rows, mode cards, approval items, tier legend |
| Accent (10%) | `var(--color-accent)` (#8b8af0 graphite; theme-dependent) / `var(--color-accent-soft)` | See reserved list below |
| Destructive | `var(--color-status-failed)` (#dc2626) | Deny action on a destructive/Tier 4 item; the "denied" decision state |

Accent reserved for (explicit — never "all interactive elements"):
- The **selected mode** in `AutonomyModeSelector` (active card: `bg-[var(--color-accent-soft)] border-[var(--color-accent)]` + a `Check` glyph in `--color-accent`, matching the existing `ThemePicker`/`ScalePicker` active-segment pattern in Settings).
- The **selected "Always"/"Ask first"** segment in each `ActionOverrideRow` (active segment `bg-[var(--color-accent)] text-white`, matching the existing `AutonomySelector`).
- The **Approve** primary button on each `ApprovalItem` (accent fill `bg-[var(--color-accent)] text-white hover:bg-[var(--color-accent-hover)]`, matching Home's primary buttons).
- The **"Balanced (recommended)"** marker text/badge — a soft accent `Pill` (`tone="accent"`).
- Focus rings (`focus-visible:ring-[var(--color-accent)]`).

Accent is NOT used for: override labels, tier-legend body text, locked rows, the "pending" approval state, or row hover (hover uses `--color-border-strong` / `--color-elevated`, matching existing rows).

**Decision / approval state colors (theme-agnostic status tokens — the PERM-04 core contract):** reuse the Phase 2 status tokens.

| State | Token | Icon (`lucide-preact`) | Pill tone | Notes |
|-------|-------|------------------------|-----------|-------|
| pending ("Needs you") | `var(--color-status-running)` #d97706 (amber) | `Clock` | `running` | Waiting on the operator. The "Needs you" amber matches the Home "Running" pill family. |
| approved | `var(--color-status-done)` #16a34a (green) | `CheckCircle2` | `done` | After one-tap approve + successful replay. Copy "Sent" / "Done". |
| denied | `var(--color-status-failed)` #dc2626 (red) | `X` / `XCircle` | `failed` | After deny. Copy "Discarded". |
| expired (TTL lapse) | `var(--color-text-faint)` muted | `Clock` (dimmed) | `neutral` | A "Needs you" item that timed out; reads muted, not alarming. |

**Locked Tier 4 rows (the trust signal — D-01, spec lines 33-37):**
- Rendered via the `ReadOnlyRow` presentation precedent: visibly non-editable, NO segmented control, NO toggle.
- A `Lock` (`lucide-preact`) icon at 12–13px in `--color-text-muted` sits before/beside the row label.
- The row label is `--color-text` but the row reads quieter than editable rows: the control slot shows a static **"Always ask"** `Pill` (`tone="neutral"`) plus the lock — never an interactive control.
- A one-line explainer in `--color-text-faint` (11px) states WHY it is locked (per spec: the lock + its short explanation is what builds trust). The lock is NOT a destructive/red treatment — it is a calm, permanent guardrail, so it uses muted/neutral tones, not `--color-status-failed`.

## Component / Interaction Contracts

### 1. Permissions section in Settings (`PermissionsSection`) — PERM-01/02/03

Added as a new `Section` in `Settings.tsx` (title `term('page.permissions')` → "Permissions", subtitle: "What your team can do on its own."). The section is the centerpiece per spec; it renders, top to bottom: the mode dial, the tier legend, then the override list.

#### 1a. `AutonomyModeSelector` — the dial (PERM-01)
- **A single prominent control** — three **radio cards** (NOT a thin segmented control; the dial must read as the primary decision). Stacked or 3-up grid (`grid sm:grid-cols-3 gap-2`), each card in `--color-elevated` with the selected card in `bg-[var(--color-accent-soft)] border-[var(--color-accent)]` + a `Check` glyph (matches the existing `ThemePicker` active pattern).
- Each card carries the mode name (12.5px, 500) + the plain-language one-liner from spec 07 (11px muted):
  - **Cautious** — "Prepares and drafts. Asks before anything leaves."
  - **Balanced** — "Acts on low-risk things. Asks to send or commit." Carries a soft-accent **"Recommended"** `Pill` (`tone="accent"`). This is the default on first run (D-11).
  - **Autonomous** — "Acts on its own. Tells you after."
- Mode is **team-wide** (D-11), not per-teammate — no teammate picker here.
- Selecting a mode fires `pushToast` `tone="success"` "Mode set to {Mode}" and persists immediately (the change is itself audit-logged server-side, D-11 — not a UI concern beyond the toast).

#### 1b. `TierLegend` — what each mode does in tier terms
- A compact, **collapsed-by-default** explainer ("How modes work" disclosure, or a small inline legend) so the operator can understand the four tiers without the dial becoming a wall.
- Renders the four tiers as four rows: tier name + one-line "what it is" + the current mode's behavior for that tier (auto / asks), reading the resolved behavior from the four-tier model. Tier 4 row shows `Lock` + "Always asks" regardless of mode.
- Body text only (no accent), `--color-text-muted` / `--color-text-faint`. This educates; it is not a control.

#### 1c. `ActionOverrideList` + `ActionOverrideRow` — fine-tune by action (PERM-02)
- A secondary `Card` below the dial, headed by a `.section-label` "Fine-tune by action" + a one-line hint "Most people never need this." (reinforces "dial, not a checkbox wall").
- ~6 capability rows (per CONTEXT discretion + spec lines 27-33), each a `Row`-style line: capability label (13px) + a small tier badge `Pill` + a **two-segment Always / Ask first control** (the existing `AutonomySelector` segmented pattern: active = `bg-[var(--color-accent)] text-white`). NOT a boolean `Toggle` — the two states are named, not on/off.
  - Research and prepare — default **Always** (Tier 1)
  - Draft messages and docs — default **Always** (Tier 1)
  - Send emails and messages — default **Ask first** (Tier 3)
  - Book or move meetings — default **Ask first** (Tier 3)
  - Post publicly — default **Ask first** (Tier 3)
  - (the locked money row renders as a `LockedActionRow`, see 1d — it lives in this list but is non-interactive)
- Each row's default reflects the current mode; an explicit override is visually marked as overridden (a small "overridden" `Pill` `tone="neutral"` or a subtle dot) so the operator sees they've departed from the mode default. Resetting to mode default is available (a small `RotateCcw` text-action, matching the Settings `AccentPicker` "Reset" precedent).

#### 1d. `LockedActionRow` — Tier 4, locked (PERM-03, D-01)
- The locked rows (per D-01): **Send money / pay invoices**, **Sign or commit to contracts**, **Permanently delete data**. Grouped visually under the override list (or inline within it), each rendered per the locked-row color contract above: `Lock` icon + label + static "Always ask" `Pill` (`tone="neutral"`) + a one-line `--color-text-faint` reason.
  - Send money / pay invoices — "Money movement can't be undone. Always asks."
  - Sign or commit to contracts — "A signature is binding. Always asks."
  - Permanently delete data — "Deletion can't be reversed. Always asks."
- These rows have **no control** — clicking them does nothing (no toggle, no segment). The lock is the entire point: it proves judgment (spec line 36). Cursor is default, not pointer.

### 2. Minimal "Needs you" approval surface on Home (`ApprovalItem`) — PERM-04, D-07

EXTEND the existing `NeedsYouCard` (`DailyLoop.tsx`) — do NOT build a parallel card. The card already renders flagged mission tasks; Phase 3 adds gated approval items into the same list (the card already says "Needs you" / "Decisions only you can make", which is exactly the contract). Gated approval items render via a new `ApprovalItem` row sibling to the existing `NeedsItem`.

Each `ApprovalItem` (compact row, `p-3`, `bg-[var(--color-elevated)]` rounded, matching `NeedsItem`):
- **What it is:** a short plain-language summary of the prepared action (e.g. "Send the proposal to Acme") — 12.5px, `--color-text`. "Ask first is cheap": this is a ready-to-send thing, approving runs the captured action, it is NOT redoing work (D-08 replay).
- **Which teammate prepared it:** `AgentAvatar` (16–18px) + teammate name, using the teammate-color treatment established in Phase 2 (`teammateColor()`).
- **Target / detail line:** who/where it goes (e.g. "to sarah@acme.com") — 11px `--color-text-muted`, truncates.
- **Tier badge:** a small `Pill` indicating sensitivity — Tier 3 `tone="neutral"`, Tier 4 (e.g. a payment) `tone="medium"` (amber) so high-stakes items read distinct.
- **Prepared-at timestamp:** `formatRelativeTime` (e.g. "4m ago"), 10–11px `--color-text-faint`, `tabular-nums`.
- **One-tap Approve / Deny:**
  - **Approve** — accent primary button (`bg-[var(--color-accent)] text-white`, `CheckCircle2` 13px). On click: optimistic → row transitions to the **approved** state chip, replays the action (D-08), fires `pushToast` "Sent" / "Done". On replay failure, row shows an honest failed state + the reason verbatim (Phase 2 honesty precedent), NOT a generic error.
  - **Deny** — secondary/ghost button (`X` 13px, `--color-text-muted` hover `--color-status-failed`). On click: row transitions to **denied** ("Discarded"). **Exception:** if the item is Tier 4 / destructive, deny is preceded by a `ConfirmModal` (`destructive`) — but normal Tier 3 deny is one tap, no modal (asking is cheap; denying a draft is cheap too).
- `ApprovalDecisionChip` renders the resolved state (pending/approved/denied/expired) per the color table; once resolved the row dims and the buttons retire (it stays briefly for confirmation, then the list refreshes it out — Phase 4 owns the persistent feed).

**Empty state** (no gated actions pending): the existing `NeedsYouCard` already handles empty ("Today" / starters on Home, or "Nothing needs you right now."). Phase 3 adds NO new empty screen — gated actions simply don't appear when none are pending. When the ONLY pending things were approvals and they clear, the card returns to its existing empty/"Today" presentation. Do not render a literal "0 approvals" (spec 03 anti-pattern: never show a zero where you can show a next action).

### 3. Inline chat ask (`InlineApproveBar`) — D-04 (light contract only)

When a Tier 3/4 action arises during a **live chat turn**, the assistant asks **inline in the chat stream** (D-04) rather than queuing — the operator is right there. This phase specifies the affordance lightly as a contract; the rich Activity held view is Phase 4 (out of scope).
- An inline bar in the chat message stream: a one-line plain-language ask ("Send this to Acme?") + a prepared-content reference + **Yes / No** affordances reusing the same Approve/Deny visual language (accent Yes, ghost No, `CheckCircle2` / `X`).
- **Yes** runs the prepared action immediately (D-04). For Tier 4, approval is **per-instance only** — approving once never sets it to Always; the lock holds (D-05). The inline bar for a Tier 4 item carries the same `Lock` affordance + "This always asks" microcopy so the operator understands the one-time nature.
- Visuals reuse tokens; no new color or type. Detailed chat-stream layout is owned by the Chat surface; this is the approve/deny contract only.

### 4. Decision / approval state visuals — color/icon/copy contract

See the decision-state color table above. Copy contract:
- **pending:** the item simply appears under "Needs you" — no separate "pending" label needed in the queue (presence = pending). The amber `Clock` chip is used only when a pending item is shown in a mixed/resolved list.
- **approved:** chip "Sent" (for sends) or "Done" (for non-send commits), green `CheckCircle2`. Toast "Sent."
- **denied:** chip "Discarded", red `X`. Toast "Discarded."
- **expired:** chip "Expired", muted. TTL/expiry copy is Claude's discretion per CONTEXT (D-07 open item); the visual is muted/neutral, never alarming.
