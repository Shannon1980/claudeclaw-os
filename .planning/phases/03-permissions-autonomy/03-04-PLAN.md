<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dashboard client → /api/permissions, /api/approvals | Untrusted HTTP mutates config + replays prepared actions; behind the token gate + mutations kill-switch + enum validation. |
| operator chat reply → inline-ask resolver | A chat "yes/no" decides a Tier 3/4 action; must not let prompt-injected text self-approve a queued item or flip mode. |
| approve → replay executor | Stored tool params are executed; allowlisted tools only, no eval. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-tier4-ui | Elevation of Privilege | LockedActionRow | mitigate | Locked rows render no control in any mode; the server-side resolveOutcome lock (plan 02) is the real enforcement — UI cannot send an Always for Tier 4 (PERM-03/D-05). |
| T-03-replay-exec | Tampering | /api/approvals approve replay | mitigate | Allowlist replayable tools (MCP direct-call + tiny Bash/Write executor); reject others honestly; parse stored JSON, no eval/shell interpolation beyond the already-gated captured command (P-3). |
| T-03-replay-twice | Tampering | approve route | mitigate | Status-guarded approve from plan 03 (L-3); contract test asserts a second approve does not replay. |
| T-03-config-validate | Tampering | PUT /api/permissions | mitigate | Enum-validate mode + override values; 400 on invalid (V5); change is audited (D-11). |
| T-03-injection-selfapprove | Elevation of Privilege | inline-ask + approvals route | mitigate | Approval decisions come from the operator over the token-authed dashboard or an explicit chat reply, not from model output; the model can only request, never self-approve; inline resolver times out to deny. |
| T-03-SC | Tampering | npm installs | accept | No new packages; reuses Preact/lucide-preact/hono already present. |
</threat_model>
