## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → gate | The model-requested tool name + input is untrusted; classifyTier must treat unknown/unrecognized input as high-risk (Tier 3+). |
| gate → audit | Decision detail is written to the audit pipeline; must carry no secret/env material. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Elevation of Privilege | resolveOutcome Tier 4 lock | mitigate | Tier 4 returns 'ask' before any mode/override branch; unit-tested with an 'always' override present (PERM-03). |
| T-03-misclassify | Elevation of Privilege | classifyTier | mitigate | Unknown tool + unknown Bash command default to Tier 3 (D-03); broad Tier 4 keyword set; never Tier 1/2 fallback. |
| T-03-cache | Elevation of Privilege | makeCanUseTool | mitigate | Never returns `updatedPermissions` — every call re-enters the gate (D-05), so no cached allow can bypass the lock. |
| T-03-failmode | Denial of Service | makeCanUseTool fail-safe | mitigate | classify/resolve throw or PERMISSION_GATE_ENABLED off → Tier 3 ask/queue, never deny-all (bricks bot) or allow-all (L-2). |
| T-03-info | Information Disclosure | audit detail | mitigate | detail is a JSON of toolName/tier/mode/outcome only; no env/secrets (L-4/V8). |
| T-03-SC | Tampering | npm installs | accept | No installs; uses already-present SDK + existing modules. |
