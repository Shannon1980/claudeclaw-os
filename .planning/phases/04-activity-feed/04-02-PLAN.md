<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser → `GET /api/activity` | Read endpoint; token + CSRF middleware already gate it app-wide. Query params (limit/before) are parsed, not interpolated. |
| stored `tool_input` / `audit_log.detail` → rendered `phrase` | Stored params cross into operator-visible text; only an allowlisted non-secret subset is surfaced. |
| client filter/tag rendering | Trust state (the tag) is computed SERVER-side; the client only renders the server's verdict. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | `describeAction` phrase map | mitigate | Phrase reads a named non-secret param allowlist only; tokens/full bodies never surfaced (ASVS V8). Pinned by the Wave-0 describeAction test. |
| T-04-02 | Tampering / Spoofing | trust-state (the tag) | mitigate | Tags derived server-side in `listActivity`; client renders, never re-derives (RESEARCH anti-pattern). |
| T-04-03 | Information Disclosure | double-counted queued action implying two distinct events | mitigate | Dedup rule (queue row canonical) suppresses the matching 'queued' audit row; pinned by the dedup test. |
| T-04-05 | Spoofing | `GET /api/activity` access | mitigate | Inherits the app-wide `requireToken` + CSRF origin allowlist (dashboard.ts:359-444); no per-route auth added. |
| T-04-SC | Tampering | npm installs | accept | Zero new packages this phase (RESEARCH audit n/a). |
</threat_model>
