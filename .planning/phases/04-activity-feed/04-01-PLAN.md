<objective>
Build the read-side engine for the Activity feed: a deterministic tool->phrase map (D-04/D-05), a curated read model that merges approval_queue + audit_log permission rows into one reverse-chronological, deduped, tag-derived, attribution-carrying feed (TRUST-01 / D-06), and two new read helpers on approval-queue.ts that later Undo work needs (TRUST-02 prep). No UI and no new write path in this plan, pure server-side read logic, fully unit-tested.

This is the foundation slice. The next plan mounts an endpoint and renders these rows on screen; nothing here is user-visible yet, so tests are the contract.

Purpose: Establish the testable, deterministic backbone every later slice consumes, the phrase map, the merge/dedupe/tag rules, and the row helpers Undo targets.
Output: src/activity-render.ts, src/activity.ts, the two new read helpers on src/approval-queue.ts, and their unit tests (authored failing-first).
</objective>
