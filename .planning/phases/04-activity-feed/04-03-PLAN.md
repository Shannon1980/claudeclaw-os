<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser → `POST /api/activity/:id/undo` | The high-risk mutation surface. Token + CSRF + DASHBOARD_MUTATIONS_ENABLED gate it app-wide; `:id` integer-validated. |
| undo-executor → MCP stdio server | The inverse is a REAL external mutation; travels the server-side scrubbed-env JSON-RPC path only, never the browser. |
| stored `tool_input` → inverse MCP params | Captured params drive the inverse; structured JSON only, no shell, no eval. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering / Repudiation | Tier-4 action undone or "undone-faked" | mitigate | Tier-4 lock is the FIRST statement in undoAction, before any dispatch (D-09); UI renders no Undo button for Tier 4 or non-allowlisted; pinned by the `-t "tier 4"` test. |
| T-04-06 | Elevation of Privilege | Arbitrary tool execution via undo | mitigate | Name-dispatch allowlist, no eval, structured JSON params only, scrubbed-env MCP spawn (mirrors replay-executor SECURITY header). |
| T-04-07 | Tampering | Double-undo (replaying an inverse twice) | mitigate | Status-guarded transition (`WHERE ... status=...`, `.changes===1`) on any undo state change (mirror approval-queue.ts:153). |
| T-04-08 | Spoofing / Elevation | Undo invoked cross-origin with leaked token | mitigate | CSRF origin allowlist + token gate + mutation kill-switch, all app-wide (dashboard.ts:359-444); the POST inherits all three. |
| T-04-09 | Information Disclosure | Inverse leaks creds via browser-side call | mitigate | Undo runs server-side via scrubbed-env MCP spawn; no `fetch()` to a provider domain from web/src (Pitfall 3). |
| T-04-SC | Tampering | npm installs | accept | Zero new packages this phase (RESEARCH audit n/a). |
</threat_model>
