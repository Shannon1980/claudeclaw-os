# Phase 4 — UI Design Contract: Activity Feed

> Visual and interaction contract for the operator-facing Activity surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Derived from the locked CONTEXT decisions (D-01..D-11), the authoritative product spec `specs/operator-product/08-activity-audit.md`, the verified data contract in `04-RESEARCH.md`, and the existing ClaudeClaw web design system (`web/src/styles/main.css`, `Pill.tsx`, `PageHeader.tsx`, `PageState.tsx`, `ApprovalItem.tsx`, `teammate.ts`). This is an EXTENSION of an established system — it does not introduce new tokens.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (existing Preact + Tailwind v4 + CSS-variable token system) |
| Preset | not applicable — shadcn is not used in this project; styling is tokens-only via `var(--color-*)` |
| Component library | none (hand-rolled Preact components in `web/src/components/`) |
| Icon library | `lucide-preact` (the `Activity` icon is already imported in `routes.ts`) |
| Font | Inter (`--font-sans`); JetBrains Mono (`--font-mono`) RESERVED for technical Audit only — Activity must NOT use mono for timestamps or detail |

**Hard project constraints (CLAUDE.md + CONVENTIONS):**
- Tokens-only styling. Every color is a `var(--color-*)`. No raw hex in `Activity.tsx` except the teammate dot, which comes from `teammateColor(id)`.
- Font weights **400 (regular) and 500 (medium) only**. No 600/semibold in this surface (the shared `PageHeader` title uses `font-semibold`; that is the one inherited exception and is acceptable since it is the shared header component, not new Activity styling).
- **No em dashes anywhere** — copy, phrase map output, empty/error states, Summarize digest. Use periods, commas, or "and".
- Activity must look **deliberately unlike Audit**: card/list visual language (like `ApprovalItem` / NeedsYou), NOT the dense monospace table of `Audit.tsx`.

## Spacing Scale

The project uses Tailwind's default 4px-based scale, applied through utility classes. The declared spacing scale for this surface contains only multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, tag inner padding (`gap-1`, `px-1` = 4px) |
| sm | 8px | Inline element spacing, row action gaps (`gap-2`) |
| md | 12px | Row internal padding (`p-3` = 12px — matches `ApprovalItem`) |
| lg | 16px | Gap between rows / vertical rhythm inside a day group |
| xl | 24px | Page horizontal padding (`px-6` = 24px — matches `PageHeader`) |
| 2xl | 32px | Day-group separation (between dated sections) |
| 3xl | 64px | Empty/loading vertical centering (`py-16` = 64px — matches `PageState`) |

Exceptions: none. The reused components (`Pill.tsx` / `StatusDot` / `ApprovalItem` button sizing) carry their own internal micro-spacing inherited verbatim from the existing design system; `Activity.tsx` introduces **no new sub-4px spacing values** of its own. Touch targets: this is a desktop Electron app, not touch, so 44px targets are not required.

## Typography

Inter throughout. Base `font-size` is 13px / `line-height: 1.5` (set on `html`). This surface declares **exactly 4 sizes** (10 / 11 / 12.5 / 14), mirroring the values already in `PageHeader`, `ApprovalItem`, and `PageState`. Hierarchy below the title is carried by **color and weight**, not by adding more sizes:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Page title ("Activity") | 14px | 500 (header component renders 600 — inherited exception) | 1.5 |
| Row action phrase (the plain-language line) | 12.5px | 400 | 1.4 (`leading-snug`) |
| Meta (who + when, "Comms · 9:12am") AND page subtitle ("What your team did") | 11px | 400 | 1.5 |
| Tag / day-group label / chip | 10px | 500 | 1.5 |

- The page subtitle "What your team did" renders at **11px / weight 400**, the same size as the meta line; it is differentiated from the meta line by the **`--color-text-muted`** token, not by a distinct size. (Collapsed from a 5th size per checker Dimension 4 fix.)
- Relative time uses `tabular-nums` (matches `ApprovalItem`).
- NO monospace anywhere on this surface. The honest failure reason on Undo is the single allowed exception ONLY if it carries a technical verbatim error — prefer plain text; if mono is used it matches `ApprovalItem`'s `font-mono` failure line at 10.5px (a reused component value, not a new declared type role).

## Color

Dark-theme app with three themes (graphite default, midnight, crimson). Activity must read correctly in all three by using only tokens. The 60/30/10 split maps to the existing token roles:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` (#0e0e10 graphite) | Page background, the feed canvas |
| Secondary (30%) | `var(--color-card)` / `var(--color-elevated)` (#1a1a1c / #222226) | Row cards, day-group containers, filter-chip active state |
| Accent (10%) | `var(--color-accent)` (#8b8af0 graphite; theme-variable) | Primary action buttons (Summarize Today, Review→approve), active nav, focus — RESERVED, see below |
| Destructive | `var(--color-status-failed)` (#dc2626) | Undo confirmation modal, honest Undo-failure text only |

**Accent reserved for (explicit list — never "all interactive elements"):**
- The **Summarize Today** header action button (filled accent, like `ApprovalItem`'s Approve button).
- The **Review** affordance's primary approve action (reuses the existing `/api/approvals` approve button styling, which is filled accent).
- The active filter chip and active sidebar nav item.
- Focus rings / hover on accent buttons (`--color-accent-hover`).
- The teammate fallback dot when an `agent_id` matches no known teammate.

**Tag colors are status tokens, NOT accent** (this is the emotional core of the surface — keep them legible and distinct from the app accent):

| Tag | `Pill` tone | Token | Hex |
|-----|-------------|-------|-----|
| You approved | `done` | `--color-status-done` | #16a34a (green) |
| Ran on its own | `neutral` | `--color-text-muted` on `--color-elevated` | grey, deliberately quiet |
| Needs you | `medium` | `--color-priority-medium` | #ca8a04 (amber) |
| Skipped / waiting on your ok | `medium` (amber) with explicit copy | `--color-priority-medium` | amber — framed as the system working, not an error |
| Denied | `failed` | `--color-status-failed` | #dc2626 (red) — only for an explicitly denied held item |
| Expired | `cancelled` / `neutral` | `--color-text-faint` | faint grey — honest "timed out, not run" |

Teammate dot color comes from `teammateColor(agent_id)`: research #a78bfa, comms #2dd4bf, content #fb7185, ops #f59e0b, fallback `--color-accent`. These are NOT part of the 10% accent budget — they are identity markers, sized at 6px.

## Layout Contract

**Page:** `PageHeader` (title "Activity", subtitle "What your team did", Summarize Today action, filter-chip tabs) over a scrollable reverse-chronological feed grouped by day.

**Per-row visual focal point:** the right-aligned `Pill` tag (Ran on its own / You approved / Needs you) is the primary visual focal point of every row — it is the accountability signal the operator scans for, so it must be the most color-saturated, immediately-legible element in the row's right rail, sitting above the quieter View/Review/Undo affordances.

**Day grouping:** a quiet day-label header (`.section-label` style: 10px, uppercase, letter-spacing, `--color-text-faint`) e.g. "TODAY", "YESTERDAY", "MON, JUN 23". Grouped by **local machine timezone** (single-user local-first app, per RESEARCH A3). 32px (`2xl`) separates day groups.

**Filter chips (D-11)** in the `PageHeader` `tabs` slot, using `Tab`: `All` · `Ran on its own` · `Needs you` · then one chip per teammate (label = teammate name, with a leading `teammateColor` dot). Active chip uses the elevated-background active state already in `Tab`.

### Per-row anatomy (left to right, single row, like `ApprovalItem`)

```
[●dot]  Sent follow-up to 3 leads                          [tag]
        Comms · 9:12am                            [View] [Undo]
```

1. **Teammate color dot** — 6px `StatusDot`-style span filled with `teammateColor(agent_id)`.
2. **Plain-language phrase** — 12.5px / weight 400, `--color-text`, `leading-snug`, `line-clamp-2`. From the deterministic tool→phrase map (D-04); honest generic ("Used Gmail", "Ran <tool>") for unmapped (D-05). Never fabricated, never hidden.
3. **Meta line** — `AgentAvatar` (16px) + "Teammate · 9:12am" (or "Ops · 6:00pm routine" when `routine_id` is present), 11px / `--color-text-muted`.
4. **Tag** — right-aligned `Pill` with the tone from the Color table. This is the per-row focal point and the accountability signal; keep it legible.
5. **Affordances** (right-aligned, conditional — see Interaction States): `View`, `Review`, `Undo`.

## Interaction States (affordance rules — load-bearing)

| Row condition | Tag | View | Review | Undo |
|---------------|-----|------|--------|------|
| `approval_queue.status='pending'` | Needs you (amber) | yes | **yes** (reuses `/api/approvals/:id/approve\|deny`) | no |
| `approval_queue.status='approved'` (has `tool_input`) AND tool on undo allowlist AND tier < 4 | You approved (green) | yes | no | **yes** |
| `approval_queue.status='approved'` but NOT on allowlist, OR tier ≥ 4 | You approved (green) | yes | no | **absent** (no greyed/dead button — Undo simply does not render) |
| `audit_log outcome='approved-inline'` (chat-approved, no `tool_input`) | You approved (green) | yes | no | **absent** (no captured params; honestly not undoable per RESEARCH) |
| `audit_log outcome='allow'` ("Ran on its own", no `tool_input`) | Ran on its own (neutral) | yes | no | **absent** (autonomous action has no captured params; cannot be undone — surfaced honestly) |
| `approval_queue.status='denied'` | Denied (red) | yes | no | no |
| `approval_queue.status='expired'` OR a held item that timed out | Expired / "Skipped: waiting on your ok" (amber) | yes | optionally Review if re-runnable | no |

**Undo honesty (D-07/D-08/D-09):**
- Undo renders ONLY when the action is genuinely undoable (allowlisted tool family with captured `tool_input`, tier < 4). Otherwise it is **absent**, never a disabled or no-op button. No "mark as undone" theater.
- Tier 4 (irreversible) shows **no Undo, ever** (D-09).
- Undo click → `ConfirmModal` (`destructive`) → `POST /api/activity/:id/undo`. On success: success toast ("Undone. The draft was deleted." style), row updates. On failure: honest verbatim reason in a toast and inline (mirror `ApprovalItem`'s `failure` line), never a generic error, never a false success.
- Floor (D-08): at least one family (label-remove or draft-delete) works end-to-end; the others ship as honest "no undo" (Undo absent) and are logged as deferred follow-ups, not faked.

**View:** opens the technical detail for that row (tool name + available params/outcome). For "Ran on its own" / inline-approved rows where only `{tool,tier,mode,outcome}` exists, View shows exactly that and says so — it does not imply more detail than was captured (D-05 completeness/honesty).

**Review:** only on pending held items; reuses the Phase 3 approve/deny flow verbatim (`/api/approvals`). Tier 4 deny goes through the `destructive` `ConfirmModal`; tier 3 deny is one tap (matches `ApprovalItem`).

**Home entry point (D-03):** a one-click affordance from Home into `/activity`. Recommendation: a compact "What your team did" link/row beneath the existing `NeedsYouCard` region (a quiet text+chevron link, NOT a second loud card competing with NeedsYou), using `--color-text-muted` with an accent hover. Exact form is Claude's discretion per CONTEXT; keep it understated so it reads as a daily-glance shortcut, not a primary CTA.

## Copywriting Contract

All copy plain-language, terse, no em dashes.

| Element | Copy |
|---------|------|
| Page title | Activity |
| Page subtitle | What your team did |
| Primary CTA (header action) | Summarize Today |
| Summarize in-progress | Summarizing… |
| Summarize result framing | A short plain-language paragraph (no em dashes, 3 to 4 sentences). On failure: "Couldn't summarize right now. The feed below is complete." |
| Filter chips | All / Ran on its own / Needs you / [teammate names] |
| Tag: autonomous | Ran on its own |
| Tag: approved | You approved |
| Tag: pending | Needs you |
| Held / parked item | Skipped: waiting on your ok |
| Denied item | Denied |
| Expired item | Expired |
| Row affordances | View / Review / Undo |
| Empty state heading | Nothing yet today |
| Empty state body | When your team does something, it shows up here. You will see what ran on its own and what is waiting on you. |
| Error state | Failed to load (heading) + the verbatim reason below (reuses `PageState` error). |
| Undo confirmation | "Undo this?" + body naming the concrete inverse, e.g. "This will delete the draft." / "This will remove the label." Confirm label: "Undo". |
| Undo success toast | "Undone." + concrete result, e.g. "The draft was deleted." |
| Undo failure toast | The honest verbatim reason. Never "Something went wrong." If a server is not connected: "Connect Gmail in Settings to undo this." |
| Phrase map fallback (D-05) | "Used Gmail" / "Ran <tool>" (tool name with the `mcp__server__` prefix stripped). Never fabricate detail. |

**Destructive actions in this phase:** Undo (deletes a draft / cancels a meeting / removes a label) and Review→Deny (Tier 4). Both go through `ConfirmModal` with `destructive`. Undo never silently no-ops.
